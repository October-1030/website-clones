# BenchmarkPage 原版契约与复刻验收

## 范围

- 目标组件：`src/components/BenchmarkPage.tsx`
- 原版证据：`.tmp/storybound-1.17.0-assets/assets/BenchmarkPage-Cp01SSnj.js`
- 原版版本：Storybound v1.17.0
- 交互模型：点击驱动的账号识别、分页刷新、单视频解析与本地文案处理

## 原版账号添加契约

原版“添加对标账号”不是通用社交平台账号导入器。

| 环节 | 原版证据 | 复刻要求 |
| --- | --- | --- |
| 输入说明 | “粘贴该账号任意一条视频的分享链接，自动识别账号” | 不提供手工空账号入口 |
| 占位文本 | `https://weixin.qq.com/sph/...  或  channels 链接` | 明确限定视频号链接 |
| 提交按钮 | “识别并添加” | 识别和保存必须是同一事务 |
| 识别接口 | `POST /v1/dajiala/feed-info`，请求体 `{ feed_info }` | 只使用原版兼容账号数据源 |
| 成功条件 | 响应必须包含 `data.v2_name` | 没有远端账号 ID 时不得保存 |
| 失败提示 | “没解析出账号，确认链接是该账号的视频分享链接” | 不得显示“添加成功” |
| 鉴权 | `X-Sb-Email` 与 `X-Sb-Fp` | 未配置时明确提示绑定原版账户 |
| 费用 | 添加账号和分页同步可能扣原版积分 | 操作前明确提示，不虚构免费 |

## 原版账号作品同步契约

| 环节 | 原版证据 | 复刻要求 |
| --- | --- | --- |
| 列表接口 | `POST /v1/dajiala/feed-list` | 使用 `v2_name` 和 `last_buffer` |
| 每页数量 | 原版界面按最多 15 条刷新/加载 | 保留分页与游标 |
| 已有账号 | 以 `accountId === v2_name` 去重 | 重复添加时更新账号而非生成空副本 |
| 同步前提 | 账号必须存在真实 `v2_name` | 本地旧数据不得伪装成可刷新账号 |

## 原版单视频解析契约

| 环节 | 原版证据 | 复刻要求 |
| --- | --- | --- |
| 输入说明 | “粘贴视频号视频分享链接” | 不宣称支持任意公开视频 |
| 占位文本 | `https://weixin.qq.com/sph/...  或  channels 链接` | 明确限定视频号 |
| 解析接口 | `GET /v1/bugpk/parse?url=...` | 保留原版兼容路径 |
| 成功条件 | `video_backup[].url` 或 `data.url` 非空 | 没有视频直链时必须失败 |
| 原版错误 | “未解析到视频直链（可能不是视频号视频链接）” | 不得生成空作品或假成功 |

## 已确认的旧版偏差

1. 把“视频号链接”泛化成“任意公开视频”。
2. 把“识别并添加”拆成“可选识别 + 独立手工保存”。
3. 保存的新账号始终写入空 `remoteId`，因此永远无法自动刷新。
4. 单视频解析没有验证媒体直链，允许空结果显示为成功。
5. 把本地资料库扩展混在原版入口中，没有清楚标明其不属于原版。

## 明确边界

- MiniMax M3 只用于文本分析，不提供视频号或抖音账号作品同步。
- 抖音账号自动同步属于额外产品功能，不是原版 Storybound 对标监控能力。
- 没有原版绑定邮箱和设备指纹时，可以完成界面与失败分支验证，但不能宣称真实账号分页同步已经通过。
